# Telegram Support & Feedback Bot

Self-hosted Telegram-бот обратной связи и поддержки. Пользователь пишет боту в личный чат, а команда поддержки отвечает из отдельной темы в супергруппе с включёнными темами.

## Возможности

- Создаёт отдельную тему форума для каждого пользователя и направляет туда его сообщения.
- Показывает и закрепляет карточку клиента в теме поддержки.
- Отправляет пользователю закреплённую карточку статуса: бот принял сообщение, передал его поддержке, поддержка ответила или обращение закрыто.
- Создаёт и закрепляет тему `Help` с командами, если подключена группа поддержки.
- Позволяет администратору отвечать пользователям из их темы, пересылать медиа, закрывать обращения и добавлять внутренние заметки.
- Поддерживает шаблоны ответов, ограничение частоты сообщений, блокировку пользователей и необязательную проверку CAPTCHA. После успешной CAPTCHA пользователь сохраняется как прошедший проверку.
- Хранит пользователей, настройки и связи сообщений в SQLite. Миграции применяются при запуске.

## Установка на Linux одной командой

Установщик скачивает готовый бинарник последнего релиза, спрашивает токен Telegram-бота и ID администратора, создаёт systemd-службу и запускает её. Поддерживается `x86_64` Linux с systemd. Нужны `curl` и `sudo`.

```sh
curl -fsSL https://raw.githubusercontent.com/govergit/feedbackbot/main/install.sh | sudo env BOT_REPO=govergit/feedbackbot sh
```

Установщик спросит:

1. Токен бота от `@BotFather`.
2. Telegram ID администратора. По умолчанию указан `8883130864`; нажмите Enter, чтобы оставить его.

Файлы устанавливаются в `/opt/tg-rust-support-bot`, база данных хранится в `data/bot.db`, конфигурация — в `.env` с правами только для владельца. Управление службой:

```sh
sudo systemctl status tg-rust-support-bot
sudo journalctl -u tg-rust-support-bot -f
sudo systemctl restart tg-rust-support-bot
```

Установка скачивает бинарник из последнего GitHub Release. Чтобы команда заработала, в репозитории должен быть опубликован релиз с приложенным файлом `tg-rust-support-bot-linux-x86_64`. GitHub Actions собирает и прикладывает его при отправке тега вида `v*`:

```sh
git tag v0.1.0
git push origin v0.1.0
```

## Подключение группы поддержки

1. Создайте супергруппу Telegram и включите в ней темы.
2. Добавьте бота в группу и назначьте администратором с правами управлять темами, закреплять и удалять сообщения.
3. В группе отправьте `/chatid`, чтобы узнать её ID.
4. Пользователь с ID администратора бота отправляет в этой группе `/addchat`.
5. Если права настроены, бот подтвердит подключение и создаст тему `Help`. Если прав не хватает, бот перечислит их; после исправления отправьте `/addchat` ещё раз.

Пользователи обращаются к боту в личных сообщениях. Для каждого создаётся отдельная тема. Команду `/addchat` может использовать только заданный администратор бота.

## Команды поддержки

Команды отправляются в теме нужного пользователя. Для административных действий аккаунт должен быть администратором группы.

| Команда | Действие |
| --- | --- |
| `/chatid` | Показывает ID текущей группы |
| `/addchat` | Подключает текущую группу поддержки; доступно только администратору бота |
| `/close` | Закрывает обращение |
| `/ban [причина]` | Блокирует пользователя |
| `/unban` | Снимает блокировку |
| `/note текст` | Добавляет внутреннюю заметку в тему |
| `.текст` или `#текст` | Отправляет внутреннюю заметку без доставки пользователю |
| `/tpl_add имя текст` | Создаёт шаблон ответа |
| `/tpl_del имя` | Удаляет шаблон |
| `/tpl_list` | Показывает список шаблонов |
| `/имя` | Отправляет сохранённый шаблон пользователю |
| `/stats` | Показывает статистику обращений |

Пользователь может отправлять текст и поддерживаемые Telegram медиа. Если включена CAPTCHA, она показывается перед первым обращением. После успешного решения проверка сохраняется для этого пользователя и повторно не запрашивается.

## Настройки

При установке через скрипт основные параметры задаются автоматически. Для ручной установки скопируйте `.env.example` в `.env` и задайте `BOT_TOKEN` и `BOT_OWNER_ID`.

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `BOT_TOKEN` | Токен от `@BotFather` | Обязательный |
| `BOT_OWNER_ID` | Telegram ID администратора бота | `8883130864` |
| `ADMIN_GROUP_ID` | ID подключённой группы; обычно задаётся командой `/addchat` | `0` |
| `DATABASE_URL` | Путь к базе SQLite | `sqlite://data/bot.db?mode=rwc` |
| `RATE_LIMIT_MAX_MSG` | Число сообщений за временное окно | `5` |
| `RATE_LIMIT_WINDOW_SEC` | Длина окна ограничения в секундах | `10` |
| `CAPTCHA_ENABLED` | Включает проверку CAPTCHA | `true` |
| `WORK_HOURS_ENABLED` | Включает сообщение вне рабочих часов | `false` |
| `WORK_HOURS_START` | Начало рабочего времени в UTC, `HH:MM` | `09:00` |
| `WORK_HOURS_END` | Конец рабочего времени в UTC, `HH:MM` | `18:00` |
| `OUT_OF_HOURS_TEXT` | Текст ответа вне рабочего времени | Сообщение в `.env.example` |
| `RUST_LOG` | Уровень логирования, например `info` | `info` рекомендуется |

## Ручная сборка и запуск

Нужен установленный Rust toolchain. Из каталога проекта выполните:

```sh
cargo build --release
cp .env.example .env
```

Заполните `BOT_TOKEN` и `BOT_OWNER_ID` в `.env`, затем запустите:

```sh
./target/release/tg-rust-support-bot
```

## Docker Compose

Скопируйте `.env.example` в `.env`, укажите токен и ID администратора, затем выполните:

```sh
docker compose up -d --build
docker compose logs -f bot
```

Данные SQLite сохраняются в `./data`.
